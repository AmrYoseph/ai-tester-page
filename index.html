🔍 فحص الموقع

فحص أوتوماتيك (من غير AI):

  • أخطاء JavaScript والـ console، والـ requests اللي فشلت أو رجعت 4xx/5xx.
  • لينكات وصور مكسورة.
  • الـ Responsive: الـ viewport، والـ horizontal scroll على الموبايل.
  • الـ Accessibility: صور من غير alt، وحقول من غير label، وزراير فاضية، والـ lang.
  • الـ SEO: الـ title والـ description والـ h1.
  • الأداء: الصفحات اللي بتاخد أكتر من 3 ثواني.
  • الأمان: HTTPS، والـ security headers، والـ mixed content.

بالـ AI:

  • Test cases لكل صفحة: functional و negative و UI و accessibility و security و usability.
  • Test cases من نوع end-to-end بتمشي على أكتر من صفحة.
  • مشاكل بيشوفها في الـ screenshots (ديسكتوب وموبايل).

"كل الصفحات": الأداة بتلف على صفحات الموقع لحد ما متلاقيش صفحات جديدة، وده مفيد للـ regression للسيستم كله.

  • فيه حد أمان 500 صفحة.
  • الصفحة اللي ليها نسخ كتير بـ parameters مختلفة (زي ?page=1، ?page=2) بتتفحص 5 مرات بس.
  • الأداة بتتجاهل لينكات Log out.

الملاحظات للـ AI

في صفحة الفحص فيه خانة ملاحظات، وليها وضعين:

  • استخدمها كسياق: الـ AI بيكتب ويشغّل تستات مركّزة على ملاحظاتك، زي acceptance criteria أو بيانات تجريبية.
  • شغّل التستات اللي كتبتها بس: بتكتب الـ test cases بنفسك بأي شكل (ليستة، أو جدول، أو Gherkin)، والـ AI بيحوّلها لخطوات ويشغّلها من غير ما يزوّد عليها.

متكتبش باسوردات في الملاحظات، لأنها بتتحفظ مع التقرير.

🎯 إزاي البرنامج بيقلل النتايج الغلط
  • الحكم مش بكلمة الـ AI بس: لما الـ AI يخلص تست، بيكتب شروط للنتيجة المتوقعة، زي "النص X ظاهر" أو "اللينك فيه /dashboard". المتصفح بيتأكد منها بنفسه، والشروط دي بتظهر تحت كل تست في "🔎 الشروط اللي البرنامج اتأكد منها".
    • ✔ متأكد بالشروط: حكم الـ AI والشروط متفقين.
    • ⚖ اتراجع: مش متفقين، أو مفيش شروط تتفحص. هنا الـ AI بيراجع الحكم بنظرة تانية أدق، وبيبص على الـ screenshot الأخيرة ونتيجة الشروط، والحكم ده هو النهائي.
    • ⚠ مش متأكد: المراجعة ما اشتغلتش (مثلاً الـ AI مش متاح)، فالحكم فضل زي ما الـ AI قاله.
  • التست اللي فشل بيتعاد مرة: لو نجح في المرة التانية بيتعلّم Flaky 🔁 بدل Failed، ومش بيتحسب bug. ونفس الكلام في الـ Test suites، وفيه زرار "أعد تشغيل الـ Flaky".
  • يستنى الصفحة تجهز: قبل ما يحكم، بيستنى التحميل والـ network يهدى، وأي spinner أو skeleton أو progress bar يختفي، وبيستنى الصفحة تبطّل تتغير.
  • ❌ النتيجة دي غلط: زرار تحت كل تست في التقرير، وتقدر تكتب معاه إيه الغلط. الموقع بيفتكره، والـ AI بياخده في الاعتبار في المرات الجاية. وفي الأرقام فوق التقرير بيظهر دقة الـ AI، يعني نسبة التستات اللي ما اتعلّمش عليها إنها غلط.
  • 🧪 بيانات تجريبية: خانة في الفورم وفي إعدادات تشغيل الـ suite، تكتب فيها يوزرز بصلاحيات مختلفة وأكواد وقيم. بتتحفظ لكل موقع (مش في التقارير)، وبتتملى لوحدها لما تختار نفس الموقع تاني. حسابات تجريبية بس.
  • 📎 ملفات: تقدر ترفق ملفات بنفس الطريقة، زي Excel فيه يوزرز، أو صور وPDF للرفع. الـ AI بيقرا اللي فيها، وكمان بيقدر يرفعها في خانات رفع الملفات على الموقع، حتى لو الخانة مخفية ورا زرار. والتستات المتسجلة بترفع نفس الملف في الـ replay. الملفات دي بتتحفظ للموقع، والـ suites بتستخدمها.

حكم الـ AI ممكن يغلط برضه، فراجع الـ Failed قبل ما تفتح bug، واستخدم زرار "النتيجة دي غلط".

  • الفيديو بيشتغل جوه التقرير على طول. والـ Trace بتحمّله وتفتحه على trace.playwright.dev (الملف بيفتح على جهازك ومش بيترفع).

🔍 Site scan

Automatic checks (no AI):

  • JavaScript and console errors, and requests that failed or returned 4xx/5xx.
  • Broken links and images.
  • Responsive: the viewport, and horizontal scrolling on mobile.
  • Accessibility: images without alt, fields without a label, empty buttons, and the page language.
  • SEO: the title, description and h1.
  • Performance: pages that take more than 3 seconds.
  • Security: HTTPS, security headers and mixed content.

With AI:

  • Test cases for every page: functional, negative, UI, accessibility, security and usability.
  • End-to-end test cases that go across several pages.
  • Problems it spots in the screenshots (desktop and mobile).

"All pages": the tool keeps crawling the site until it finds no new pages — useful for regression of the whole system.

  • There is a safety limit of 500 pages.
  • A page that has many copies with different parameters (like ?page=1, ?page=2) is checked only 5 times.
  • The tool skips Log out links.

Notes for the AI

The scan page has a notes box with two modes:

  • Use as context: the AI writes and runs tests focused on your notes, such as acceptance criteria or test data.
  • Run only the tests I wrote: you write the test cases yourself in any format (a list, a table or Gherkin), and the AI turns them into steps and runs them without adding any.

Don't put passwords in the notes: they are saved with the report.

📋 Requirements testing
  1. Enter the site link, and log in if needed.
  2. In the requirements box, write the Epic, user story, task description or acceptance criteria.
  3. Click Write & run the tests.

The tool then:

  • Skips the automatic checks entirely and only crawls the pages to learn the site's structure.
  • Saved site map: the first time, it saves the pages it found. Later runs start the tests straight away, without crawling. If the site changed, tick 🔄 Crawl the site again.
  • Targeted crawl: it starts with the pages whose link or link text contains words from the requirements, and sends only the 40 most relevant pages to the AI.
  • The AI splits the text into numbered requirements (REQ-1, REQ-2…) and writes, for each one, the positive case, the negative and edge cases, plus end-to-end scenarios.
  • It runs the tests and produces a 📋 Requirements coverage table: each requirement with the tests that cover it and its status (passed / failed / incomplete / not covered).

📎 Files with the requirements

Attach files with the 📎 Attach files button, drop a file on the box, or paste an image into it (Ctrl+V):

  • Images (designs, screenshots, diagrams): the AI looks at them itself.
  • Excel (xlsx), PDF, Word (docx), CSV and text files: the text in them is extracted and sent to the AI as part of the requirements.

Files stay private and are never shared. The maximum file size is 25 MB.

With Jira or Azure DevOps connected, a story-number box appears above the requirements. Type the story number, like PROJ-123 in Jira or 4567 in Azure DevOps, and click ⬇ Pull the requirements. The title, description and acceptance criteria are filled in, and any bug opened from this test run is linked to the story.

📄 The report
  • At the top: the run status, the AI that ran it, the login status, a ⏹ Stop button and a ＋ New test button.
  • ⏳ Time left: a countdown based on the tests already done. With "All pages", it shows how many pages have been reached until the tests start.
  • The numbers: pages, issues, Critical/High, test cases, Passed and Failed.
  • Tabs: Test Cases, Issues and Pages, with filters and search.
  • 📄 View report: opens the report neatly in a popup, to print or download.

🎯 How wrong results are kept down
  • The verdict isn't just the AI's word: when the AI finishes a test, it writes checks for the expected result, such as "text X is visible" or "the URL contains /dashboard". The browser verifies them itself, and they appear under each test in "🔎 Checks the program verified".
    • ✔ Verified by checks: the AI's verdict and the checks agree.
    • ⚖ Reviewed: they disagree, or there were no checks to run. The AI takes a second, stricter look at the last screenshot and the check results, and that verdict is final.
    • ⚠ Not verified: the review couldn't run (e.g. the AI was unavailable), so the verdict stays as the AI gave it.
  • A failed test runs once more: if it passes the second time it is marked Flaky 🔁 instead of Failed, and isn't counted as a bug. The same applies in Test suites, which have a "Rerun flaky" button.
  • Waits for the page to be ready: before judging, it waits for loading and network activity to settle, for spinners, skeletons and progress bars to disappear, and for the page to stop changing.
  • ❌ This result is wrong: a button under every test in the report, with room to say what's wrong. The site remembers it and the AI takes it into account next time. The numbers above the report show the AI's accuracy: the share of tests not marked as wrong.
  • 🧪 Test data: a box in the form and in the suite's run settings for users with different roles, codes and values. It is saved per site (not in the reports) and fills in automatically when you pick the same site again. Test accounts only.
  • 📎 Files: attach files the same way, like an Excel sheet of users, or images and PDFs to upload. The AI reads them and can also upload them into file fields on the site, even when the field is hidden behind a button. Recorded tests upload the same file on replay. The files are kept for the site and used by its suites.

The AI's verdict can still be wrong, so review Failed tests before opening a bug, and use the "This result is wrong" button.

🎬 Video and trace for every test

Every test is recorded as a video and a Playwright Trace. The trace shows every step: the page, the DOM, the network and the console.

  • The video plays right inside the report. Download the trace and open it at trace.playwright.dev (the file opens on your machine and isn't uploaded).
  • They are kept only for tests that didn't pass, or for every test if you prefer.
  • Each test runs in its own copy of the logged-in session (cookies, localStorage and sessionStorage), so it can be recorded on its own.
🐞 Bugs in Jira or Azure DevOps

Next to every Failed test there is a 🐞 Open bug button, and above the report an Open bugs for failed tests button. The bug is opened with:

  • The steps, the expected result and the actual result.
  • The screenshot and the video as attachments.
  • A link to the story, if the run came from one.

Once it is opened, the button turns into a link to the bug.

💬 Your comments to the AI on each test case

Under every test case there is a comment box, e.g. "use /debug instead of /admin" or "add step X", with a Save comment button:

  • The comment is saved for the whole site.
  • In any later run on the same site, the AI reads all your comments and follows them. A test with the same title gets its own comment.
  • In Test suites: saving a comment on a test deletes its old recording, and the AI runs it again following the comment.
⚙️ Run options
  • Safe mode (default): the browser blocks any request that changes data (POST/PUT/PATCH/DELETE) and disables submit, delete and pay buttons. To let tests submit forms, tick "Allow data changes" — on a test environment only.
  • 👀 Show the browser: opens a Chrome window so you can watch the tests run, with each step slowed down a little to follow. You may see several windows at once, because 3 tests run at the same time. Don't close a window while it runs.
  • Limits: up to 1000 test cases per run.
  • Tests run at the same time: depends on the AI: Gemini 6, Mistral and Groq 3, Ollama 2.
⚡ Why the tests got faster
  • Several steps per request: the AI plans up to 4 steps at once, like "fill the email, fill the password, click Log in". If the page changes midway, the rest is dropped and it looks at the new page.
  • Fewer screenshots: a screenshot is sent to the AI only when the page changed since the previous step.
  • No repeating: if the page hasn't changed after several steps, the AI is told to decide right away instead of repeating itself. It also sees the browser's validation messages (like "Please fill out this field").
